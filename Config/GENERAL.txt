#--- hardware feature gates (必须显式打开，否则下面相关 kmod/tool 被静默丢弃) ---
# ImmortalWrt 把「设备类支持」拆成一组语义门控包 (package/system/hardware-support):
#   audio-support / input-support / video-support / accel-support / hidraw-support ...
# 关键点: kmod-* 与部分 userspace 用 **bare DEPENDS**（即硬 depends on）挂在门控包上,
# 例如 sound.mk 的 `kmod-sound-core DEPENDS:=audio-support +kmod-input-core`、
# libevdev 的 `DEPENDS:=input-support`。门控包 =n 时, 依赖它的整族包会在
# `make defconfig` 产物里**整条消失**（连 "# ... is not set" 都不写），
# 于是本文件请求的 kmod-sound-core / kmod-usb-audio / usbutils / usbmuxd 会被
# 无声丢弃 —— 这属于"配置残留"必须消除。
# （此前 R28S 只是碰巧: aic8800 的 `+AIC8800_SDIO_BT_SUPPORT:input-support`
#   顺带选中了 input-support, 而 RT28/JDC 没开 aic8800 就全丢, 不可依赖。）

# ⚠ 必开: eMMC / 大分区机型的 overlay 会被 fstools **自动选成 f2fs**。
#   fstools/libfstools/common.c 的 use_f2fs():
#       ret = (BLKGETSIZE64(bdev) - overlay_offset) > F2FS_MINSIZE;  /* 100 MiB */
#   overlay_offset = align_up(squashfs bytes_used, 64KiB)（rootdisk.c），也就是 rootfs
#   分区里 squashfs 之后的空闲空间。>100MiB 就 `mkfs.f2fs`，否则 `mkfs.ext4`。
#   我们所有板子的 rootfs 分区都远大于固件本身（亚瑟 2G 大分区 GPT / RT28 512M /
#   R28S 1024M）→ 必然命中 f2fs 分支。此时若镜像里没有 mkfs.f2fs 或 f2fs.ko，
#   overlay 建不出来，系统静默退回 ramoverlay（纯内存根），现象就是
#   「能改配置、重启全丢」——亚瑟刷机后配置不保存的真因。
#   上游同 target 的 eMMC 设备即如此处理:
#     ipq60xx.mk: Device/link_nn6000-v1  DEVICE_PACKAGES := ... kmod-fs-f2fs f2fs-tools
#   （f2fs-tools 提供 mkfs.f2fs/fsck.f2fs，见下方 system tools 段。）
